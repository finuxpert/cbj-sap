# SAP Tools Dashboard - Documentation
Location: /home/sadmin/sap/

## 1. Overview
This project is a web-based toolkit designed for SAP Basis & Infrastructure Operations. It provides a suite of client-side tools to analyze logs, compare system snapshots, and visualize performance metrics without requiring a dedicated backend server.

**Key Features:**
- **Local-First**: All data processing (parsing logs, analyzing Excel files) happens in the browser. No data is uploaded to a server, ensuring privacy and speed.
- **Tools**:
  - **Comparer**: Analyzes "WP-SCOUT" logs / System Snapshots to identify resource eaters (CPU, Mem, localized Work Process analysis).
  - **Analyzer**: Processes ST03N Workload Analysis exports (Excel/CSV) to give insights into transaction performance.
  - **Others**: Placeholders for Backup, Deploy, Rollback, Logs, Metrics, Charts, Settings, Uploader.
- **Tech Stack**: React 19, Vite, Recharts (Visualization), XLSX (Excel processing), Dexie (IndexedDB), Tailwind-like CSS variables (Vanilla CSS).

## 3. Key Components

### A. Core Application (`src/App.jsx`)
- Uses a custom **Hash Router** for navigation (e.g., `#/tool/comparer`).
- Supports global keyboard shortcuts (e.g., `Ctrl+K` for search).
- Dynamically loads tools using `React.Suspense` and `React.lazy` to keep the initial bundle size small.

### B. Tools (`src/tools/`)

#### 1. Comparer (`ToolComparer.jsx`)
- **Input**: Text logs (Snapshot format).
- **Features**:
  - Parses proprietary "WP-SCOUT" or standard snapshot formats.
  - Scores severity based on CPU, Memory, Swap, and Work Process age/memory.
  - Visualizes "Offenders" (Recurring bad jobs/transactions).
  - Generates "Evidence" text for copy-pasting into incidents/reports.

#### 2. Analyzer (`ToolAnalyzer.jsx`)
- **Input**: ST03N exports in XLSX or CSV format.
- **Parsers**:
  - Time Profile
  - Workload Overview
  - Transaction Profile (Standard)
  - Top DB Accesses
  - Top Response Time
- **Features**:
  - Joins data from multiple exports by Transaction Code (TCode).
  - Categorizes performance issues (DB-heavy vs Wait-heavy).
  - Virtualized table for high-performance rendering of large datasets.

### C. Shell Scripts

#### `sap-deploy.sh`
- **Usage**: `sudo DO_BACKUP=1 ./sap-deploy.sh`
- **Function**:
  - Optionally runs `sap-backup.sh` first when `DO_BACKUP=1`.
  - Runs `npm ci` / `npm install` and `npm run build`.
  - Deploys the `dist/` folder to `/var/www/html/sap`.
  - Sets permissions and reloads Nginx.

#### `sap-deploy-staging.sh`
- **Usage**: `sudo ./sap-deploy-staging.sh`
- **Function**:
  - Wraps `sap-deploy.sh` with `BASE_PATH=/sap-staging/`.
  - Deploys to `/var/www/html/sap-staging`.
  - Lets users test at `http://192.168.10.1/sap-staging/` before publishing to `/sap/`.

#### `sap-backup.sh`
- **Usage**: `sudo ./sap-backup.sh`.
- **Function**:
  - Backups source `/home/sadmin/sap` to `/home/sadmin/Backup/sap-src`.
  - Creates a `.manifest.txt` with metadata (git commit, versions, timestamp).
  - Manages retention (keeps last 20 backups).

#### `sap-rollback.sh`
- **Usage**: `sudo ./sap-rollback.sh` or `sudo ./sap-rollback.sh /home/sadmin/Backup/sap-src/sap-src_YYYYmmdd_HHMMSS.tar.gz`.
- **Function**:
  - Restores a source backup.
  - Rebuilds Vite.
  - Deploys to `/var/www/html/sap`.
  - Reloads Nginx.

## 4. Development & Deployment

### Run Locally
```bash
cd /home/sadmin/sap
npm install
npm run dev
# Open http://localhost:5173
```

### Deploy to Production
```bash
cd /home/sadmin/sap
sudo DO_BACKUP=1 ./sap-deploy.sh
```
*Note: The deploy script assumes Nginx is installed and the user has sudo privileges for /var/www/html.*

### Deploy to Staging
```bash
cd /home/sadmin/sap
sudo ./sap-deploy-staging.sh
```

Use staging for ChatGPT/Codex test iterations. Production `/sap/` is not changed until `sap-deploy.sh` is run.
This staging environment runs on `server-vm`.
